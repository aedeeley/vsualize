# 0.2.3: live capture clarity and music-only motion

## Desktop changes

- Explicit LIVE/quiet/gated/connecting/error/partial/demo/stopped states, captured spectrum, master level and onset indicator in Audio.
- Per-source raw RMS dBFS, gated-state diagnostics, sample rate, channels, packet count and analysis age from WASAPI snapshots.
- No automatic synthetic fallback or saved-demo restart. Browser starts with no audio selected.
- Music-only motion default with an exact stationary transport after a short silence tail. Feedback freezes its last image instead of accumulating quantization changes.
- Faster transient attack/release and bounded sound-driven exposure shared by all 26 effects. Gentle peaks remains enabled.
- Explicit A/B comparison disables audio for rendering only. Capture meters continue; a warning remains visible during comparison.
- Optional pinned source/level monitor. Capture errors and synthetic modes cannot disappear entirely behind a closed menu.
- Serialized audio restarts, malformed-packet checks, stale-energy clearing and recovery on resumed native packets.
- Source fingerprints prevent launcher reuse of stale executables. UPDATE-WINDOWS.cmd rebuilds; BUILD-INSTALLER.cmd produces a local unsigned installer after checks.
- The 0.2.2 Windows native-caption guard is unchanged.

## Settings migration

An `audioBehavior: 2` marker migrates the old idle-animation default to off once.
Old default response 1.25 changes to 1.6; custom response values are kept.
Source, device, gains, favorites, colors, visual, layout and menu placement remain.
Re-enabling idle drift after this migration persists normally. Demo is session-only.

## Acceptance on Windows

Build and confirm version 0.2.3. Play/pause through the chosen output endpoint;
test microphone and both, gain zero, gate too high, unplug/reconnect, sleep/wake,
selected/default-output changes, then test native transparency and window controls.
A successfully compiled executable is still not proof of hardware behavior.

## Build environment limitation

This delivery was prepared in Linux with TypeScript and Chromium available.
Rust and a Windows toolchain were not available; dependency download attempts
could not resolve the package hosts. No Windows executable is included.
The files change the desktop project, not the user's installed binary or repository.
