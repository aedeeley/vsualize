# Vsualize 0.2.2: continuous musical motion and native-frame hardening

Based on the supplied Vsualize 0.2.1 archive. No remote repository was modified.

## Motion

`src/motion.ts` is an endpoint-independent musical transport. Positive eased velocities are integrated into persistent travel, turn, flow, color and animation phases. A decaying beat therefore slows the journey instead of subtracting the distance it just added. Changing Flow speed or Music response cannot multiply an old time value into a new scene position.

Bass contributes strongly to travel; mids drive turn and shape evolution; highs affect palette progression and accents. Per-band peak following has a floor so gated silence is not normalized to full-scale. Independent transient envelopes use quick attack and slower release. Onset events use native beat rises or positive spectral change, with a cooldown. There is no fabricated BPM estimate.

The Music response setting defaults to 1.25 and is separate from Flow speed (0.65), Amplitude (1.1), and capture sensitivity. Existing persisted settings are preserved; a missing response value receives the new default. Source changes reset input history without rewinding accumulated phases.

All 26 shader bodies have been updated. Major changes:

- Ripple/Glass: independently aging traveling impulses plus continuous surface advection; no flash-setting reduction of wave energy.
- Tunnels/roads/stars: audio-driven forward travel, rather than raw-bass positional jumps.
- Geometric layers: continuous turn plus expanding/entering layers with edge fades.
- Fractals: forward Mandelbrot voyages with overlap crossfades; continuously evolving Julia/bloom parameters instead of direct bass changes to the recurrence.
- Organic/particle effects: persistent advected/orbiting fields, rising merging blobs and audio-driven feedback flow.
- Spectrum/Cascade: fractional history scrolling between sample updates.

Gentler beat peaks now reduces the visual beat-flash envelope without reducing the transport's forward momentum. It still does not suppress all rapid color changes or motion.

## Native-frame workaround

The screenshot has a faint native-looking upper row and a brighter custom row. Source inspection finds only ONE `.window-actions` element. The latter row is retained unchanged.

`src-tauri/src/native_frame.rs` removes `WS_CAPTION` from the live host HWND and caption-bearing descendants using Win32 style APIs, then refreshes cached frame metrics only after a style actually changes. A reentry guard prevents recursive frame notifications. Other styles remain intact. It is called during setup/ready, drag, focus, resize and movement. The transparent host uses `noRedirectionBitmap: true`.

This is a targeted native workaround, not a verified fix for every WebView2 version. It does not disable DWM composition, sample the desktop, replace the window procedure, pin an obsolete browser runtime, disable minimize/close, or alter other top-level applications. HRESULT or Win32 success in a build would still not prove the compositor no longer paints a ghost.

Primary references:

- Report with transparent windows and caption artifacts: https://github.com/tauri-apps/tauri/issues/14764
- Same class of issue despite decorations/shadow disabled: https://github.com/tauri-apps/tauri/issues/14859
- Windows frame style and cached-metric rules: https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowlongw
- Tauri window configuration: https://v2.tauri.app/reference/config/

## Required Windows acceptance checks

Close every old instance, including the tray icon. Extract the update into a new folder and run START-WINDOWS.cmd, or overlay an existing project and run REBUILD-WINDOWS.cmd. Verify the Settings panel identifies version 0.2.2.

1. Play music in Desktop mode. Compare soft sections, percussion and silence; the scene should advance throughout the track and coast after pulses. Microphone and Both need separate checks.
2. Compare Music response 0, 1.25 and 2. Flow speed should change overall pace without a phase jump; Pause should freeze rendering.
3. Show controls, drag repeatedly, click another application and back, resize all edges, switch monitors, minimize/restore, and enter/exit fullscreen. Confirm only the working custom control row appears.
4. Test solid and transparent backgrounds over wallpaper and another window. Test taskbar hiding and tray recovery.
5. Save build.log if compiling fails. A remaining ghost row needs its screenshot and WebView2 runtime version; browser tests cannot resolve that native compositor behavior.

No compiled Windows executable or installer is supplied by this patch. Native build and device tests were not possible in the authoring environment.
