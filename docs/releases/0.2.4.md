# 0.2.4: remove native caption painting, keep the app controls

## Why this is different from the previous attempt

The previous implementation cleared WS_CAPTION and requested a frame redraw.
It did not intercept subsequent native caption-paint or activation messages.
The user's screenshot shows that attempt was insufficient. The markup itself
contains a single working minimize/fullscreen/quit row; deleting it would remove
the wrong controls.

The replacement installs a SetWindowSubclass callback on the main HWND and its
same-thread, same-process child wrapper windows. WM_NCPAINT is handled without
calling the native caption painter. WM_NCACTIVATE accepts activation without
painting a caption, except minimized windows retain default processing.
WM_STYLECHANGING prevents caption flags from coming back. Root minimize/maximize
and system-menu operation flags are preserved; child wrappers lose their native
caption-button flags. Client paint, input, focus, window operations and sizing
messages continue down the existing subclass chain. WM_NCDESTROY removes the hook.

DWM non-client rendering is disabled only for the host window; this does not
turn off desktop composition. Theme attributes suppress native caption/icon
painting. Theme refreshes are reentrancy-guarded to avoid notification loops.
The first window show occurs after guard installation. Deferred child-creation
refreshes and existing focus/size/move refreshes protect later wrapper HWNDs.

No opaque rectangle is painted over the visualizer. No shared runtime is
modified, no process is injected, and no WebView2 version is downgraded.
Foreign-process or foreign-thread WebView windows are not hooked.

## Scope

Audio input, analyzer, renderer, motion engine, effects, palettes, thumbnails and
settings keys are unchanged from the supplied 0.2.3 source. UI changes are only
the version label. The lower three buttons keep their existing native commands.
The middle button remains Fullscreen, as before; this patch does not change its
behavior to a different maximize implementation.

## Validation boundary

This source patch is not an already-installed fix. Native compilation and visual
verification are pending on Windows. Browser checks establish that the working
buttons were preserved, NOT that the extra OS buttons are gone. Five Windows-only
regression tests exercise actual Win32 messages in temporary native windows;
they have been added but not run in the authoring environment. The normal Windows
launcher runs them via cargo test after building.

A compositor artifact in an unguarded WebView2 subprocess would need additional
runtime-specific investigation. Do not claim this patch was visually verified
from a browser screenshot.
