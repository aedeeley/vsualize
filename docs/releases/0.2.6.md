# Vsualize 0.2.6: music response

This is an update to the desktop application's source, not a precompiled installer.
All 26 existing effects remain. This release changes how sound shapes them rather
than adding a different collection.

## What was getting lost

Several presets primarily showed continuous travel plus small changes in light
or geometry. For example, the old cube used a radius of `.63 + bass * intensity
* .012`: about a two-percent range at normal amplitude. More speed or more gain
could not turn that into a clearly articulated shape change.

The native spectrum is a logarithmic display representation. Arithmetic averaging
of those bins diluted narrow notes, and using those display levels again as broad
movement controls limited contrast. The new visual-response layer reverses that
display curve before calculating RMS spectral-band energy. It cannot reconstruct
values already clipped to the native display ceiling.

## New response layer

- Independent sustained low, mid and high energy changes shape and surface detail.
- Positive changes in amplitude and within-band spectrum generate short attacks.
  A held packet or held tone does not produce a new attack every animation frame.
- Each frequency bin uses bounded, slowly adapting scaling, fast attack and
  shorter release. Silence and a noise floor are retained.
- Movement clocks remain integrated: a beat does not rewind forward travel.
- Structural impact is separate from light intensity. The existing gentle-peaks
  option is labelled **Softer light flashes** and no longer weakens geometry.
- Waveform details and frequency-local components are more prominent. The Music
  response slider controls these as well as motion.

These are frequency and onset features, not instrument isolation or a BPM tracker.
Bass attacks are not guaranteed to be kick drums, nor are high attacks guaranteed
to be hi-hats. The result depends on the actual recording and capture level.

## Recommended settings without losing preferences

Open Visuals and select **Use recommended music response** once after updating.
It restores Music response 1.6, Amplitude 1.1, Flow speed 0.65 and music-only motion.
It also exits the A/B comparison mode. It does not restart capture or change the
selected effect, palette, favorites, audio source, devices, contributions or gain.
Existing custom settings otherwise stay as they were.

To evaluate live input, use the compiled Windows executable, select Audio >
Desktop and the playback device actually in use. Watch the live meters, then try
Ripple Classic, the cube, petals, starflight or the highway. Compare rhythmic
passages against quieter sections and use the existing response comparison control.

## What is intentionally unchanged

All native Rust implementation files, native caption suppression, capture APIs,
Windows logging/setup/update scripts, package dependencies, and 4px CSS clipping
are unchanged relative to 0.2.5 plus the corner patch. Cargo and Tauri configuration
only receive the version change. The response work runs in the shared TypeScript
renderer and shaders, using the existing native audio packet contract.

No GitHub upload, DNS change, automatic installation, recording or audio upload is
performed. The ZIP is source that must be rebuilt on Windows.

See TEST-REPORT-0.2.6.md for measured results and the remaining Windows boundary.
