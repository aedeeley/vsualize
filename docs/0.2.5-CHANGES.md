# 0.2.5: repair the native build configuration and reveal real errors

## Evidence and scope

The supplied build transcript reports 58 successful frontend tests, followed by
"Windows compilation failed". It omits the Tauri/compiler diagnostic. It is not
an application crash dump, and it cannot establish the compiler's exact cause or
that setup fails in the same way.

Inspection of the 0.2.4 source identifies a concrete blocker:
`app.windows[0].noRedirectionBitmap`. The current development documentation
contains this option, but the **released** `tauri-v2.11.6` configuration source
and `tauri-utils 2.9.3` WindowConfig do not. That parser denies unknown fields.
The field is removed. The prior source test that incorrectly required this field
was corrected, and regression checks now reject it.

This fix does not replace dependencies with pre-release Tauri packages, downgrade
WebView2, change graphics drivers, or delete any build cache. Caption-guard Rust
code and all audio/visual code are kept, apart from the diagnostics version label.

## Logging

The old launcher relied on Start-Transcript plus unredirected native commands.
The new common helper runs authored native commands through CMD, merges stderr
into stdout **inside CMD**, and writes each line to both the console and a flushed
UTF-8 log. This avoids treating ordinary native stderr as a terminating
NativeCommandError in Windows PowerShell 5.1. Failure is based on the process exit
code; the command and code are recorded explicitly. Commands are fixed by these
scripts; the helper is not an arbitrary user-input shell interface.

Build and prerequisite installation have separate logs. The previous log is
copied before a new one starts. The batch wrappers pause after failure and return
the same failure status. Setup no longer treats every winget failure as a possible
successful installation: only the documented already-installed/no-applicable-
update statuses are accepted alongside success.

## Compatibility check

`check-desktop-config.mjs` is deliberately a small **window-key** checker, not a
complete JSON Schema validator. It checks against a released-runtime field list
and, when invoked for a desktop build, the schema in the locally installed Tauri
CLI. It also detects mixed source version identifiers. The actual CLI and Rust
compiler remain authoritative for full configuration, types and linking.

## Validation boundary

The authoring host has Node/TypeScript, but no Windows/PowerShell/Rust environment.
The Windows logging integration test is included and explicitly skipped there.
It will parse all PowerShell scripts and exercise native stdout, stderr, failed
exit codes and log rotation when npm test runs on Windows. No successful Windows
build or caption removal is claimed. Any further error should now be captured in
build.log, rather than hidden behind a generic compilation-failed message.
